# Obsidian engagement, v0.9.57

The generic ENTICE withdrawal could persist because the player follows the alien. Separation remained below the withdrawal exit threshold, so Obsidian kept thrusting away across the unbounded world. Firing alone in the previous tests did not establish a useful engagement.

Obsidian now has a dedicated close / brake / engage pilot. It pursues when beyond blade engagement range, faces against its velocity and applies ordinary source thrust to brake once in range, then coasts and aims. Its existing close-defense fire ring handles nearby danger. Projectile avoidance can no longer repeatedly overwrite its engagement command with another outward escape. Velocity is not reset, position is not clamped, and physical stats, source thrust cadence, gun costs and blade phases are unchanged. This is an adaptation for Orbit Forge without the original arena wrapping.

A long full-loop diagnostic remained engaged and landed blade damage beyond 100 simulated seconds. The new regression starts Obsidian 25 blocks away, facing away at full speed, then checks that it returns within 18 blocks by 15 seconds and keeps firing and landing hits in each subsequent 20-second sample through one minute. It runs alongside all 25 full encounter regressions. The new Obsidian test resets only the test world encounter counter, so it exercises one first-tier ship instead of accidentally escalating to a larger, stronger fleet. The existing mixed-progression checks are retained unchanged. A separate attempt to isolate every old test at tier one exposed a zero-primary case for Crescent Runner; that separate ship issue is not resolved by this Obsidian change. No player save or encounter progression is reset by the game change. Run node tools/test-combat.cjs and python3 tools/check.py. Automated tests do not establish visual equivalence with the original game.
